## What changed

- Launch checks actual Homebrew configuration/root and packaged components without enabling protection or registering startup. Missing root, service/transport failure and unreadable status have separate messages; unsafe mutations remain disabled.
- Fresh settings remain SAFE/OFF. Existing tier, intent and domain overrides are not reset by launch.
- One **Start protection after reboot** setting reflects the actual link. It resumes the saved ON/OFF choice, not an automatic enable now. Foreign entries are refused. Raw diagnostics are under **Advanced**.
- **Disable and remove startup** confirms first, performs rollback, verifies live cleanup, removes only the owned link and verifies again. Preferences remain saved. Failure means keep the app installed.
- Already-loaded keeper/guard treat app-directory disappearance as terminal OFF and refuse subsequent recovery re-arm. Firewall detachment is verified before stopping the serving resolver; a failed detach retains service and retries.

Direct removal is not an instantaneous or unconditional guarantee. It requires a running loaded supervisor, eventual lock availability and functioning firewall operations. Guard checks at its normal 10-second tick; cleanup can take longer under lock contention/failure. If both supervisors have been externally killed or firewall cleanup remains permanently impossible, automatic recovery cannot be promised. Prefer the confirmed cleanup action. The ordinary uninstall leaves preferences/logs and potentially a harmless dangling startup symlink; it has no uninstall callback and does not write system partitions.

## Disable and recovery

Normal route: **Disable and remove startup**, confirm, wait for **Protection OFF; app startup removed. Ready to uninstall.** Refresh and verify actual networking before uninstalling.

If the UI cannot operate but the package is still present, an authorized root console can use the same fixed helpers:

```sh
APP=/media/developer/apps/usr/palm/applications/io.github.furkanbayrak.lgtvblocklist
sh "$APP/scripts/rollback.sh"
sh "$APP/scripts/check.sh"
# Only after RESULT=off/reason=user-off and live pointer=off,
# filter=down and no active owned rules:
sh "$APP/scripts/startup.sh" remove
sh "$APP/scripts/check.sh"
```

A `returnValue`/exit code alone is not successful cleanup: read the result and live probe. If rollback reports cleanup failure, leave code and serving resolver intact so cleanup can retry. Never kill the resolver first, flush all firewall rules, remove foreign hooks or delete state to hide the failure.

If the app container is already gone, loaded supervisors should clean up; verify DNS rather than assuming it. If recovery fails, reinstall the saved exact package using the prepared independent route and invoke rollback, or use the separately agreed reboot/network recovery procedure. Reinstalling preserves saved intent; do not reboot with an ON startup choice until rollback/startup removal is verified. No fabricated universal emergency command substitutes for the device's verified recovery route.

## Host-side screen observation and remote navigation

`tools/tv-observer.py` runs on the owner's computer using an existing,
host-key-verified SSH connection. It is not part of the app/IPK. No TV daemon,
new listening port, pairing secret, telemetry or persisted device script is
installed. Requires Python 3, OpenSSH and a rooted TV with the existing Luna
capture/network-input services.

```sh
export LGTV_HOST=YOUR_VERIFIED_TV_ADDRESS
python3 -B tools/tv-observer.py capture
python3 -B tools/tv-observer.py key RIGHT
python3 -B tools/tv-observer.py smoke
```

`capture` sends no input. `key` captures before and after one key; `smoke`
sends UP/DOWN/LEFT/RIGHT once each with captures. It checks the app is foreground
before input and stops on errors; it never retries or power-cycles. `launch`
opens only LG TV Blocklist. ENTER/BACK require `--allow-activation`, which is a
technical interlock, not owner authorization to enable protection or alter state.
Inspect the current screen before any activation. Use one controller; the
foreground check cannot exclude a racing physical key or a system overlay.

Captures use DISPLAY at explicit 1920x1080. On TVs with the older service name,
select `--capture-service tv.capture`; no silent service fallback occurs.
Luna calls use an SSH PTY because this G1 otherwise exits with no reply;
PNG transfer is base64-framed to avoid terminal byte conversion. The tool
checks Luna success and PNG chunk checksums/completeness, and removes its own
private `/tmp/lgtv-observer.*` capture directory on normal completion.
After a transport interruption, check for leftovers before removing only that
session's directory; no general `/tmp` cleanup is authorized.

Each invocation prints a fresh owner-only evidence directory beneath
`${XDG_STATE_HOME:-$HOME/.local/state}/lg-tv-blocklist-tv/`.
It contains screenshots, their hashes, foreground observations, installed
app metadata and the action/error record. Images may contain personal content;
do not commit/upload the raw evidence. No HTTP screen server is started.

Host-only failure/safety checks:

```sh
python3 -B -m unittest discover -s tests/observer -p 'test_*.py'
```

A successful capture/input transport is **not** an app acceptance PASS.
Screensavers, video/DRM layers and stale/overlaid screens can obscure the UI.
Screen evidence cannot prove DNS routing, playback quality or recovery by itself.

baseline still follow the authorization, human-review and recovery gates above.
