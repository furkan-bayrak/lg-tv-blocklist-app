# S6 - Safe/Strict tiers and the domain-list mode

Status: planned (2026-10-05). Owner decisions already taken; this plan turns them into tasks.

## Context

The app currently ships ONE frozen list (Strict-derived) generated by tools/build-filter-input.mjs, and has no tier switch and no domain list (docs/design.md records tiers and fine-tuning as deferred). The owner decided on 2026-10-05: fresh-install default tier = SAFE; users may switch to STRICT; and a new domain-list mode where the user opens all domains and toggles individual ones off/on to self-debug STRICT. Firmware/OTA blocking is explicitly NOT the app's job (inform only; point users at LG TV settings or the Homebrew Channel switch).

Two facts from research (see the session map and docs/research reports):
- Upstream lg-tv-blocklist src/{safe,strict,zones}.txt entries are `hostname # TAG: free text` with TAG in {SAFE,STRICT,ZONE}. scripts/build.py discards annotations. There is NO machine-readable category field upstream; categories (telemetry/ads/ACR/OTA/ThinQ/Channels) exist only as prose.
- The privileged bridge reaches root only through HBC luna `exec`, whose payload is {command} ONLY: no stdin, no params, no file-write method (verified against webosbrew/webos-homebrew-channel services/service.ts @ main / v0.7.3). Reverse direction works: exec returns stdout, so constant `cat`-style commands can READ fixed-path state.

## Decisions this plan implements

- D13a is NARROWED, not abandoned: no UNVALIDATED content may enter a command string. The one new dynamic payload rides a single choke point in the bridge, is limited to the charset [a-z0-9.-_=] plus newline, is one `name=on|off` line per domain, and is re-validated by the receiving script before it is written. There is no quoting, no shell metacharacter, and no caller-controlled command.
- Domain metadata is generated, not hand-written: tools/gen-domains.mjs produces app/filter/domains.json ([{name, tier, category, zone, note}]) plus the two tier lists app/filter/filter-input-{safe,strict}.txt. The generated file is committed so the owner can review and correct every row; the classifier is a documented regex over the upstream free text with an explicit `other` fallback, and is expected to be replaced by an upstream category field later.
- Overrides are keyed by domain NAME (not position, not index), stored in $STATE/overrides.txt as `+name` (force blocked) or `-name` (force allowed), and survive list updates. The effective block set is preset(tier) with overrides applied on top.
- A domain covered by a zone anchor is not individually toggleable: the UI says it is covered by that zone and points at the zone row instead. Zone rows are toggles for the whole zone and carry a blast-radius warning.
- Toggles are batched: the user edits, then presses Apply. Apply re-materialises the filter input and restarts dnscrypt-proxy, which is a real interruption (kill -9, relaunch, sleep 2, canary retries), so it must never happen per toggle and the UI must say so.
- Reset to preset clears overrides for the active tier.

## S6a - tiers (small, shippable first)

- T1: extend tools/build-filter-input.mjs (or add tools/gen-domains.mjs and call it from it) to emit two lists, filter-input-safe.txt and filter-input-strict.txt, from the same pinned upstream ref; keep the existing generation rules (=exact per domain, zone anchors from zones.txt). Pin the upstream ref in the generated header as today.
- T2: app/scripts/common.sh - teach materialize_config() to pick the list for the active tier from a new state key `tier` (default safe when unset, so a fresh install is SAFE) and to merge overrides at the existing seam (the copy at common.sh:225 becomes: read the chosen preset list, apply overrides, write $STATE/filter-input.txt). Do not change the on-disk format of $STATE/filter-input.txt.
- T3: bridge + UI: add a tier selector (SAFE/STRICT) that saves the state key and triggers the existing apply path; status parser and main.js render the active tier. Keep the existing protection panel intact.

## S6b - domain-list mode

- T4: tools/gen-domains.mjs emits app/filter/domains.json, sorted by category then name, with tier, category, the covering zone (if any) and the upstream note text; the category mapping table lives in the script as an explicit, reviewable list.
- T5: new script app/scripts/overrides.sh with three fixed entry points: `save` (reads the validated payload on stdin, re-validates, writes $STATE/overrides.txt atomically), `clear` (reset to preset), and `list` (prints the effective set as `name=on|off` lines for the UI). No other input path.
- T6: bridge API: one new fixed command constant for each entry point (payload only in `save`), plus the pinned exact-string set in tests/ts/bridge.test.mjs extended to match; the serializer/validator that builds the payload lives in its own small module with its own unit tests.
- T7: UI list view: grouped by category, one row per domain with an on/off state, keyboard focus like the existing buttons, a "covered by zone" row state that is not directly toggleable, a zone row with a blast-radius warning, an unsaved-changes indicator, Apply, and Reset to preset.
- T8: help text in the UI and README: what SAFE and STRICT actually do (STRICT may degrade the store, may break LG account login, kills ThinQ and LG Channels and freezes firmware updates), that toggles exist to self-debug STRICT, that firmware-update freezing belongs to LG TV settings or the Homebrew Channel switch, and that the lists come from lg-tv-blocklist (CC BY 4.0 attribution).

## Verification

- tests/ts: serializer/validator unit tests (including rejection cases: uppercase, shell metacharacters, quotes, semicolons, newline injection, unknown domain not present in domains.json, oversized payload), merge unit tests, status/main rendering tests, bridge pinned-string tests.
- tests/shell: overrides.sh save/clear/list against the sandbox (atomic write, re-validation rejects bad payloads, unchanged behaviour when the file is absent).
- tests/g1: on-device harness for this feature is BLOCKED until the T9 window has run; the tree tests/g1/** is frozen until then. Plan it as a follow-up, not part of this change.
- Existing gates must stay green: npm run check:es5, npm run check:node8, npm run test:ts, npm run test:shell (test:shell has three pre-existing fixture failures unrelated to this work).

## Rollback

Every commit is revertible on its own. State rollback: delete $STATE/overrides.txt and set `tier` back to `safe` (the app tolerates a missing overrides file by design). The generated lists and domains.json are regenerable from the pinned upstream ref.

## Out of scope

Fetching lists from the network (S7 owns the update pipeline), firmware-update blocking, per-domain statistics or logging beyond what exists, and any change to tests/g1/** before the T9 window has run.
