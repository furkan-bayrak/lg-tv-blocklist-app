# S6 - Safe/Strict tiers and the domain-list mode

Status: planned (2026-10-05). Owner decisions already taken; this plan turns them into tasks.

## Context

The app currently ships ONE frozen list (Strict-derived) generated by tools/build-filter-input.mjs, and has no tier switch and no domain list (docs/design.md records tiers and fine-tuning as deferred). The owner decided on 2026-10-05: fresh-install default tier = SAFE; users may switch to STRICT; and a new domain-list mode where the user opens all domains and toggles individual ones off/on to self-debug STRICT. Firmware/OTA blocking is explicitly NOT the app's job (inform only; point users at LG TV settings or the Homebrew Channel switch).

Two facts from research (see the session map and docs/research reports):
- Upstream lg-tv-blocklist src/{safe,strict,zones}.txt entries are `hostname # TAG: free text` with TAG in {SAFE,STRICT,ZONE}. scripts/build.py discards annotations. There is NO machine-readable category field upstream; categories (telemetry/ads/ACR/OTA/ThinQ/Channels) exist only as prose.
- The privileged bridge reaches root only through HBC luna `exec`, whose payload is {command} ONLY: no stdin, no params, no file-write method (verified against webosbrew/webos-homebrew-channel services/service.ts @ main / v0.7.3). Reverse direction works: exec returns stdout, so constant `cat`-style commands can READ fixed-path state.

## Decisions this plan implements

- D13a is NARROWED, not abandoned: no UNVALIDATED content may enter a command string. The one new dynamic payload rides a single choke point in the bridge, is limited to the charset [a-z0-9.-_=] plus newline, is one `name=on|off` line per domain, and is re-validated by the receiving script before it is written. There is no quoting, no shell metacharacter, and no caller-controlled command.
- Domain metadata is generated, not hand-written: tools/gen-domains.mjs produces app/filter/domains.json ([{name, tier, category, zone, note}]) plus the two tier lists app/filter/filter-input-{safe,strict}.txt. The generated file is committed so the owner can review and correct every row; the classifier is a documented regex over the upstream free text with an explicit `other` fallback, and is expected to be replaced by an upstream category field later.
- Overrides are keyed by domain NAME (not position, not index), stored in $STATE/overrides.txt as `+name` (force blocked) or `-name` (force allowed), and survive list updates. The effective block set is preset(tier) with overrides applied on top.
- A domain covered by a zone anchor is not individually toggleable: the UI says it is covered by that zone and points at the zone row instead. Zone rows are toggles for the whole zone and carry a blast-radius warning.
- Toggles are batched: the user edits, then presses Apply. Apply re-materialises the filter input and restarts dnscrypt-proxy, which is a real interruption (kill -9, relaunch, sleep 2, canary retries), so it must never happen per toggle and the UI must say so.
- Reset to preset clears overrides for the active tier.

## S6a - tiers (small, shippable first)

- T1: extend tools/build-filter-input.mjs (or add tools/gen-domains.mjs and call it from it) to emit two lists, filter-input-safe.txt and filter-input-strict.txt, from the same pinned upstream ref; keep the existing generation rules (=exact per domain, zone anchors from zones.txt). Pin the upstream ref in the generated header as today.
- T2: app/scripts/common.sh - teach materialize_config() to pick the list for the active tier from a new state key `tier` (default safe when unset, so a fresh install is SAFE) and to merge overrides at the existing seam (the copy at common.sh:225 becomes: read the chosen preset list, apply overrides, write $STATE/filter-input.txt). Do not change the on-disk format of $STATE/filter-input.txt.
- T3: bridge + UI: add a tier selector (SAFE/STRICT) that saves the state key and triggers the existing apply path; status parser and main.js render the active tier. Keep the existing protection panel intact.

S6a review fix F1 (2026-10-05): `tier_list()` used to fall back to the legacy single list whenever the active tier's file was missing. That file IS the strict list (123 entries incl. 8 zone anchors), so a TV whose `filter-input-safe.txt` had been deleted materialized the aggressive list while state, check.sh and the panel all said `tier=safe` - a silent fail-closed on a damaged install. The fallback is now limited to the case it was written for (BOTH tier files absent = a genuine pre-tier bundle, still journaled as `materialize-fallback reason=no-tier-file`); if the active tier's file is missing while its sibling exists, `tier_list()` refuses (rc 1) and journals `materialize-fail reason=partial-tier-files tier=<tier>`, so `materialize_config()` fails before it touches the live `$STATE/filter-input.txt` and every caller takes its existing fail-open path (apply: `RESULT=fail`, `reason=materialize`, rules untouched).

## S6b - domain-list mode

- T4: tools/gen-domains.mjs emits app/filter/domains.json, sorted by category then name, with tier, category, the covering zone (if any) and the upstream note text; the category mapping table lives in the script as an explicit, reviewable list.

S6b T4 note (2026-10-05): `tools/gen-domains.mjs` is deliberately NOT chained from `tools/build-filter-input.mjs` - it reads the annotated `src/*.txt` (which the tier lists throw away) as well as the name lists, and T1's reproducibility fixture has no annotations to classify. It runs second, against the same pinned checkout, and verifies that pin by reading it out of the `filter-input-strict.txt` header that ships next to the output; it then refuses, before writing anything, if the checkout HEAD differs, if a source file is missing, or if the names it derives disagree with the names those tier lists block. `app/filter/domains.json` therefore holds exactly the 115 distinct domains the two shipped lists name (20 safe, 87 strict-only, 8 live zone anchors). Note the arithmetic: the strict list's 123 ENTRIES are 115 exact rules plus its 8 anchors repeated as bare zone entries, so domains.json matches on names, not entries. `zone` is the COVERING anchor - an anchor's own row carries its own name, a RETIRED anchor (`lgunifiedsmart.com`, still in the strict list as an exact entry) covers nothing and keeps `zone: ""`, and a covered row is the UI's cue to point at the anchor row instead of toggling it directly. Categories come from one ordered table in the script, most specific first, so prose that names several things is filed under what the endpoint does on the wire; `zone` is assigned from the tier and never from prose (a non-anchor row cannot land in the zone group by accident), and prose the table does not name is `other` - a domain is never dropped over its prose, and a domain with no upstream annotation is emitted with an empty note.
- T5: new script app/scripts/overrides.sh with three fixed entry points: `save` (reads the validated payload on stdin, re-validates, writes $STATE/overrides.txt atomically), `clear` (reset to preset), and `list` (prints the effective set as `name=on|off` lines for the UI). No other input path.

S6b T5 note (2026-10-05): `overrides.sh` stores the DIFFERENCE against the active tier's preset, never a copy of the state. The preset is resolved by `tier_list()` - the same F1 helper `materialize_config()` uses - so the baseline is the tier list this install ships (legacy `filter-input.txt` only when both tier files are absent, refusal on a partial install, journaled under the `overrides-*` tag), and it is never read back from the materialized `$STATE/filter-input.txt`: a saved-but-not-yet-applied change reads back as saved, and a stale or hand-edited materialized file can never become the baseline. `save` reads one payload on stdin (the only input path; a payload-shaped argv is refused), accepts `name=on|off` per changed row (sparse, and a dense list is valid and idempotent - unmentioned rows keep their stored state), ignores blank lines and a missing trailing newline, and caps the payload at 512 lines / 16384 bytes. Every line is re-validated before anything is written - shape, `[a-z0-9._-]` charset (no spaces, quotes, semicolons, `$`, `*`, backslash, `(`), a name no longer than 128 characters (the same bound `overrides_apply` uses, `OVERRIDE_NAME_MAX`), membership in `domains.json`, no duplicate - and any failure rejects the whole payload: exit 2, nothing written (an existing file stays byte-identical), reason journaled as `overrides-reject reason=<r>[ line=<n>]` with no payload text; environmental failures exit 1 (`no-preset`, `no-domains`, `read-failed`, `write-failed` as `overrides-fail reason=<r>`). The candidate state is computed with `overrides_apply` itself (a copy of the preset LIST, then the stored diff, then the payload), so the writer can never store a line the reader would interpret differently; the written diff is the name-set difference (sorted `LC_ALL=C`), an empty diff REMOVES the file (`lines=0 cleared=1`) so the preset stays authoritative and a preset that later grows an entry is not fought by a stale `-` line, and a candidate with no entries is refused (`reject-last`, rc 2, nothing written). The file is installed with one `mv` from a `$$`-unique scratch name (scratch names are per-process because the UI can refresh while a save runs), mode 0600, and every exit path removes this run's scratch files. `list` prints one `name=on|off` line per `domains.json` row in file order, no header and no `RESULT` block, and reads OFF an anchor row the active preset does not block - which is how the SAFE tier shows its 8 zone rows, since it ships no bare anchor. Documented limitation: a zone row switched ON under the SAFE tier adds only the exact apex rule (`+name`), because whole-subtree blocking is a bare-anchor property of the STRICT preset; the zone's covered domains are SAFE rows themselves and stay blocked either way. Entry points: `save`/`clear` print `RESULT=overrides` + `reason=saved|cleared`; `list` prints data only.
S6b review fix F1 (2026-10-05): `reject-last` was asked only of the tier that was ACTIVE when the save ran, but the stored diff is a diff against whatever tier is active, so a tier switch re-baselines it. Under STRICT, turning the 20 SAFE rows off left 95 of the strict list's 115 exact rules (plus its 8 anchors), which the old check accepted without a word - and `tier.sh safe` then materialized the SAFE preset minus those rows, i.e. the 173-byte comment header alone: the panel reported protection while nothing was blocked. Both seams are now closed. (a) At save time the question is asked of EVERY preset list this bundle ships (`ov_shipped_presets`: both tier lists when present, the legacy list only when neither tier file exists - the same fallback rule `tier_list()` applies, written out because the question is "which lists could this install ever materialize", not "which one is active"); the refusal is journaled as `overrides-reject reason=reject-last tier=<t>` so the journal names the preset that would have been emptied, the active tier's candidate is the one the diff is taken against, and a diff that survives every preset is still saved (no over-rejection). (b) At materialize time `materialize_config()` builds the effective list at a `$$`-unique scratch path in `$STATE` and publishes it with one `mv` only when `list_entry_count()` finds at least one entry (a line that is neither a comment nor blank): a candidate with 0 entries fails closed with `materialize-fail reason=empty-list`, the live `$STATE/filter-input.txt` stays byte-identical and no scratch file is left behind, so every caller takes the fail-open path it already has (`apply.sh`: `RESULT=fail`, `reason=materialize`, rules untouched) and the previous list keeps protecting. That second seam is what covers a diff that pre-exists (a hand-edited file, an app version older than this fix, or a preset that shrank under it), and `list_entry_count()` is the same definition check.sh reports as `entries=` (review F3).
- T6: bridge API: one new fixed command constant for each entry point (payload only in `save`), plus the pinned exact-string set in tests/ts/bridge.test.mjs extended to match; the serializer/validator that builds the payload lives in its own small module with its own unit tests.

S6b T6 note (2026-10-05): `src/overrides.ts` (global `LgOverrides`) owns the payload grammar; `src/bridge.ts` owns the commands. `clearOverrides`/`listOverrides` are ordinary fixed constants. `saveOverrides` is the ONE wrapper that takes data — and it does not take a payload: it takes the UI's changed rows plus the app's domain list and runs them through `LgOverrides.serialize()`, so the only bytes that can ever reach the command are that function's output. The command is a literal head plus payload plus literal tail, `printf '%s' '<payload>' | sh <APP_DIR>/scripts/overrides.sh save`, and the head/tail form exists because the HBC service has no argv or stdin parameter (its exec payload is `{ command: string }`) and runs the string through `child_process.exec`, i.e. a shell — the same thing the existing `&&`-chained register command already relies on. Before composing, `saveOverrides` re-checks the payload with `LgOverrides.isSafePayload()`, a whitelist that accepts only `[a-z0-9._-]` names, one `=`, `on|off`, LF separators, the 512-line/16384-byte caps and no empty line: the accepted alphabet contains no quote, backslash, space, `$`, backtick, glob, `;`, `|`, `&`, `<`, `>` or CR, so the single quotes around the payload cannot be escaped and the payload can only ever be the bytes it looks like. A refused payload is never sent: the callback gets `returnValue: false` and an `errorText` in the same voice as `diagnose()` (including when `js/overrides.js` is missing from an incomplete package — `clear`/`list` deliberately keep working then, because neither validates anything). `serialize()` mirrors the writer's checks in the writer's own order — shape, charset, 128-character bound, membership in the domain list the UI passed in, duplicates, then the caps — and reports the writer's own reason words, so the UI refuses locally with an actionable message instead of a silent device-side rejection; the writer stays the boundary and re-validates everything, and a name the UI's list does not know is refused on both ends (`thinq.com` is not a row in domains.json; only the 115 real rows are). The grammar and its numbers live in two languages, which is why tests/ts/overrides.test.mjs parses `OV_MAX_BYTES`/`OV_MAX_LINES` out of overrides.sh and `OVERRIDE_NAME_MAX` plus the `[!a-z0-9._-]` class out of common.sh and fails on drift, and why 21 new tests also pin the exact command strings, the refusal path (hostile names, injection attempts, duplicates, non-boolean states, empty payload: nothing is sent), and — end to end — that the composed command really runs: the test executes it against the shipped `overrides.sh` in a temp state dir and asserts the stored diff and the `list` round trip. `app/index.html` loads `js/overrides.js` before `js/bridge.js`.
S6b review fix F2 (2026-10-05): the Verification bullet above used to list `reject-last` as covered by tests/shell, and that claim was false - the suite had no reject-last assertion at all (nothing built a payload whose candidate would be empty), which is exactly how F1 survived a green suite. The two cases now exist (T5 case 14: reject-last against the active preset AND against the preset a tier switch would make active, with the counterfactual counted from the shipped lists rather than hardcoded; T5 case 15: the materialize empty-list seam, its fail-open apply path and its positive control), and the bullet above now describes what the tests actually do.
- T7: UI list view: grouped by category, one row per domain with an on/off state, keyboard focus like the existing buttons, a "covered by zone" row state that is not directly toggleable, a zone row with a blast-radius warning, an unsaved-changes indicator, Apply, and Reset to preset. The zone row's blast-radius warning is TIER-AWARE (review F4): under STRICT that row blocks the whole subtree, under SAFE it adds only the exact apex rule - and "covered by zone, not directly toggleable" means the row is not the switch the user should flip, NOT that the row is off (its own row can be ON, which is exactly what the SAFE half of the note now says it buys). The protection state it renders is not the filter/rule dot alone: the schema-4 `entries=` count is part of it, and a materially degraded count (all the way down to ONE entry - a zone row left ON while every row it covers is OFF is enough) renders as an attention state, never as a healthy ON (review F3; the writers deliberately still accept a small list, because "block one domain on purpose" is a legitimate debug state).
S6b review fix F3 (2026-10-05): the rule "a save may never leave the list with no entries" is not the same as "the list still blocks what the user asked for": under SAFE, a zone row left ON plus all 20 SAFE rows OFF stores a diff that materializes a ONE-entry list (`=lge.com`), which the old 14-key check.sh could not show - `filter=up`/`rule=on` come from the process and the DNAT rule, and `rules_present` does not count blocked_names content. Rejecting a small list in the writer was considered and rejected: "block exactly one domain" is a legitimate debug state and a threshold would refuse it. Instead the state is made visible and T7 is required to render it (bullet above): check.sh emits `entries=<N>` (schema 3 → 4, the fifteenth → sixteenth key, appended last) counting the entries of the effective materialized list with `list_entry_count()` - the same definition, from the same file in common.sh, that `materialize_config()` uses to refuse publishing an empty list, so a published list never reads 0 and "0 entries" can only mean "nothing is in place". The parser rejects the old schema-3 block outright rather than defaulting the count, for exactly the reason it rejects schema 2: an older check.sh cannot know the number.
S6b review fix F4 (2026-10-05): the shipped zone copy promised more than the tier delivers. Upstream's anchor note ("umbrella zone - kills all lge.com subdomains in adblock format") is true of STRICT, which ships the anchor as a bare whole-subtree entry, and false of SAFE, which ships no bare anchor at all (measured: `grep -cx 'lge.com'` = 1 in strict, 0 in safe/override). domains.json is UI copy, so the generator applies one documented transformation to anchor rows only (anchorNote()): the upstream prose is kept and the tier split is appended - "(blocked as a whole zone under STRICT; under SAFE this row blocks only <name>)" - while names, tiers, categories and zones stay untouched, an unannotated anchor still keeps note "" (nothing is invented; the UI falls back to its own zone warning), and the never-drop rule is unaffected. T7's warning is tier-aware for the same reason (bullet above). Regeneration verified from the pinned checkout: tools/build-filter-input.mjs reproduces filter-input-safe.txt and filter-input-strict.txt byte for byte (cmp), the generator rewrites domains.json with only those 8 anchor notes changed (115 rows, same order, same categories), and a second run is byte-identical.
S6b review fix F5 (2026-10-05): the two ends disagreed on the reason for a junk payload that breaks two rules at once. 600 lines of the same valid `ad.lgappstv.com=off` (11400 bytes, i.e. under the byte cap) came back as `duplicate` in the UI and `oversized` in the TV's journal, because serialize() checked the lines before it measured the payload while overrides.sh measures bytes and lines before it reads a single line. The writer's order is: read, bytes, lines, no-domains, then one pass over the lines (bad-shape, bad-charset, name-too-long, unknown-domain, duplicate), then `empty-payload` after its loop - and serialize() now runs in that order: a TS-local shape pre-pass (the writer never receives an array or a boolean; bytes it cannot parse are its `bad-shape`), then the caps measured from what the payload will hold (bytes, then lines), then the per-line checks, then `empty-payload`, then the isSafePayload invariant. Only the reason a doubly-bad payload reports changes; no payload that used to be accepted is refused, and the caps are still exact (128 x 124-char names = 16384 bytes passes, 129 lines do not). tests/ts/overrides.test.mjs now pins the two ends against each other instead of against a copied string: it asserts the TS reason for the 600-duplicate case, then runs the repo's real overrides.sh in a temp state dir with the equivalent 600-line payload and compares rc, journal reason word and "nothing stored"; a second case pins `bad-charset` + line=2 on both ends.
- T8: help text in the UI and README: what SAFE and STRICT actually do (STRICT may degrade the store, may break LG account login, kills ThinQ and LG Channels and freezes firmware updates), that toggles exist to self-debug STRICT, that firmware-update freezing belongs to LG TV settings or the Homebrew Channel switch, and that the lists come from lg-tv-blocklist (CC BY 4.0 attribution).

## Rollback

Every commit is revertible on its own. State rollback: delete $STATE/overrides.txt and set `tier` back to `safe` (the app tolerates a missing overrides file by design). The generated lists and domains.json are regenerable from the pinned upstream ref.

## Out of scope

Fetching lists from the network (S7 owns the update pipeline), firmware-update blocking, per-domain statistics or logging beyond what exists, and any change to tests/g1/** before the T9 window has run.
