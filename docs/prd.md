# PRD — LG TV Blocking App (companion to furkan-bayrak/lg-tv-blocklist)

> Summary of the approved design spec (`2026-09-14-lg-tv-app-design.md`, decisions D1–D16, approved 2026-09-14). Mechanics live in the spec; this PRD records what we build, for whom, and how we verify it.

## 1. Problem Statement

Rooted LG webOS TV owners who have no server, no Pi-hole, no AdGuard and no extra hardware have no simple one-switch, TV-local way to stop LG's ads and telemetry. Today the job takes shell expertise — hand-written hosts hooks and firewall rules over SSH, or a network-wide blocker running on separate hardware. This app closes that gap: install from the Homebrew Channel, choose Safe or Strict, block using lists published by `furkan-bayrak/lg-tv-blocklist`, and restore the TV to normal at any time — no server, no router changes, no extra hardware. It is not a Pi-hole replacement (network-wide protection stays Pi-hole's job); for Pi-hole/AdGuard homes it still adds value by guarding the TV's own DNS escape routes. Honest limits are documented publicly, the same discipline as the blocklist repo. (Spec §1)

## 2. User Stories

- **The non-expert rooted user** — "installed Homebrew Channel, nothing more": opens the app, sees a self-checking first-run list (rooted ✓ / Homebrew Channel ✓ / lists reachable ✓, with plain-language hints on failure), presses **Set up blocking**, and watches progress to "Protection is active." The main screen then shows one ON/OFF switch, a Safe/Strict choice (Safe is the default), live counts read from the installed lists, and the list date. OFF pauses blocking without removing anything. If a TV system update removes root, the app says so plainly with a re-root hint. (Spec §4, D1, D8, D15)
- **The same user with a breakage**: opens **Something not working?**, sees the known Strict trade-offs in plain words, and switches to Safe with one tap — protection stays on; no terminal, no uninstall. (Spec §4, D15)
- **The user who wants everything gone**: chooses **Restore TV to normal**, confirms once more, and the TV returns to stock behavior — everything the app ever created (scripts, boot pointer, rules, config) is removed. (Spec §4, §5, D1)
- **The co-maintainer/tester (rugk)**: uses the update flow (Safe changes apply quietly; Strict changes require one-tap confirmation; "Update now" always available) and runs repeatable test drills on his TV — clean-room install, restore drill before any blocking test, agreed time windows with his veto, and stated log/data handling. (Spec §4, §5, D4, D10, D14, D16)
- **A Pi-hole/AdGuard household**: keeps its network blocker; the app's filter sits in front of the TV's own lookups so both the network's lists and the app's list apply — no setting needed for the network. (Spec §1, D12)

## 3. Implementation Decisions

Confirmed choices; each traces to D1–D16. Mechanics (exact algorithms, command tables, schemas, thresholds) stay in the spec and its Slice 0 deliverables — this section is the summary level.

- **Product shape (D1, D2, D3, D8):** a standalone TV-local app. v1 = install/setup from the Homebrew Channel (no SSH knowledge), on/off switch, Safe/Strict modes mapping to the repo's tiers, list updates pulled from our repo, restore-to-normal — store-grade foundation from day one. One switch + one safe/strict choice; machinery stays hidden; plain words, never jargon. Pro mode (per-domain fine-tune toggles, custom lists, advanced DNS settings) is deferred to later milestones on the same app.
- **Blocking layers with an honesty rule (D12, §3, §7):** (a) an on-TV blocking filter — the v1 core; (b) a managed hosts overlay; (c) a firewall sneak-cut (redirect :53 to the local filter, drop :853) where a firewall exists, degrading cleanly where it does not. Layer efficacy is measured per-layer in Slice 0 (hosts-only vs filter-only vs combined); if hosts proves near-no-op under the proxy it is demoted to "coexistence shim, supplementary" — the app never presents three equal layers.
- **DNS-guard architecture B — fail-open by construction (D12):** the app's own small filter takes over the TV's lookup desk where the system resolver sat; every lookup is checked against our list (blocked → nowhere; everything else → the network's own upstream, auto-learned — no hardcoded third-party DNS; Pi-hole/AdGuard coexist, no v1 setting). Ordered apply: (1) filter starts on a side port (e.g. 5353) and self-checks BEFORE any system change; (2) only then is the system resolver switched to the filter; (3) end-to-end verify (canary resolve + known-blocked name) before commit; (4) on ANY failure, the pre-recorded resolver is restored FIRST and the filter killed second. "Worst case = protection off, TV works" is an ordering guarantee, not a hope. The keeper owns DHCP-change handling: poll `connectionmanager/getStatus` on a bounded interval plus on network-change signals, canary-verify the upstream, and on upstream failure restore system DNS (fail-open) — never retry forever. Build-out is gated by the criteria-bound G1 validation spike (Slice 0); failing the gate means guard-only mode with honest limits.
- **Keeper order and status trust (D13):** on filter death → restore system DNS FIRST (TV instantly works) → bounded background restart (~3 attempts, exponential backoff) → re-flip only after canary verification. Steady state is "protection off, TV works"; no network-manager restart flap loops. Status is derived from live probing at read time (filter socket alive, firewall `-C` checks, hosts-section hash) — never from a cached file; any status file is root-only.
- **Scripts-only HBC bridge, pinned contracts (D7, D13):** privileged work runs as scripts through the Homebrew Channel's Luna service. Fixed-command discipline: enumerated fixed entry points (no arguments) or one documented argv convention with quoting rules; no user input or downloaded content ever becomes part of a command; no `eval`, no sourcing of fetched files; fetched lists are allowlist-validated line-by-line (a rejected file keeps the previous version). Each script self-verifies (apply → verify → commit, else rollback + report). Status is one machine-readable block delimited `@@STATUS-BEGIN`/`@@STATUS-END` with `key=value` lines; all other output goes to stderr/log — the UI never parses un-delimited stdout. `/exec` ceilings are measured on both devices in Slice 0; long operations use a sentinel-file protocol. Service-swap trigger: status fidelity <100% over repeated applies, or any double-apply observed → the on-device service variant becomes a v1 blocker.
- **List updates (D9, D14):** fetch only from `furkan-bayrak/lg-tv-blocklist` over HTTPS; SHA256 fingerprint check against the repo's published sums; one-step-back safety copy covering all layers as one version (single pointer); auto-check at most once per day on open plus manual "Update now"; bundled snapshot fallback for offline installs; freshness shown as age bands in days (gentle hint, never blocking). Gating: Safe changes apply quietly; Strict changes require one-tap confirm. "Atomic" = single version pointer + ordered apply (filter config → hosts → firewall) + verify-each + journal (intent logged first, pointer flipped last); the boot script reconciles pointer-vs-live on every boot. Release signing (minisign-style detached signature, public key bundled in the IPK) is priced in Slice 0; if not adopted, docs say honestly: "SHA256 = corruption check, not tamper-proof."
- **Coexistence — scoped ownership, never fight (D11):** the app creates only clearly-labeled pieces — its own marked section in the hosts overlay (one sheet: extend the active sheet if one exists, else create it; removal erases exactly its section) and labeled firewall chains of its own (fixed jump position, `-C`-guarded jumps, re-create-if-missing tolerance). HBC update-blocking entries stay untouched; foreign hooks/rules are detected and reported calmly (one info line + hand-off guide), never deleted. Hosts edits always resolve the currently-mounted sheet, assert exactly one bind-mount, and refuse-and-report on stacked mounts.
- **Honest copy (D15):** live counts read from the installed lists — word "domains", no hardcoded numbers, no safety absolutes. Counted unit = unique effective hostnames in the installed filter input (region filtering applied first); counts display live (Safe count; Strict count labeled "total") with the list date always adjacent; the "bundled" date is shown distinctly from the "updated" date. New users start on Safe; Strict carries the honest warning. IPv6 honesty: when a v6 default route / global address is detected, status reads "Active — IPv4 only; IPv6 DNS unfiltered on this TV" with the same prominence as the Active badge — never a buried log line.
- **Device floor and claims (D6, D16):** claim only what is tested on real hardware. Catalog claim: **"webOS 5+ works (possible degradation: no firewall sneak-cut layer)"**; "verified" is reserved for devices actually tested — launch fleet: owner's G1 (webOS 6) and rugk's TV (owner reports LG C5 / webOS 25; exact model/OS recorded at test time). Recruiting a webOS 4/5 tester before launch is a stated prerequisite; the webOS 25/26 install workaround is documented. App updates (store): settings and blocking survive; the app folder is replaced in place with the pointer staying valid. Store compliance from day one: hook symlinked, never copied; no writes to system partitions; real-TV test evidence; AI-use disclosure.
- **Stack (spec §3):** UI = HTML + TypeScript compiled at build time to conservative JavaScript — TypeScript pinned to an exact version with a committed lockfile, ES5 target, no polyfill assumptions, no framework, no runtime dependencies, `async`/`await` and generators banned or transpiled, linted against post-ES5 builtins, and the built bundle tested on the oldest claimed engine; spatial navigation for the remote; first-run checklist, main screen, help, and restore confirmation screens plus progress/needs-attention states. Privilege bridge = Homebrew Channel Luna service (`/exec`, `/spawn`, `/getConfiguration`; zero declared permissions). Glue = POSIX shell for apply/verify/rollback/status/keeper-boot — explicitly not the filter vehicle; shellcheck plus tests with a stubbed PATH. Filter = small Go static binary delivered via the IPK, reuse-first (Slice 0 prices `dnscrypt-proxy` `blocked_names` off the shelf before we write our own; if we write our own: proven DNS library + fuzz tests, `--selftest` for verify-then-commit, armv7+arm64 build matrix, hot config reload, project-owned CVE tracking); Node-based forwarders are rejected. Boot = one pointer in the TV's startup list (symlink, per store rules) → minimal boot script (reconcile pointer-vs-live; if ON, re-apply; then exit) — deliberately tiny, it can never block TV startup. Config = small local state (on/off, mode, list version); logs small and rolling. UI / scripts / config / logs stay cleanly separated so the later service swap stays internal.

## 4. Testing Decisions

- **Slice 0 — the criteria-bound validation spike (the D12 gate):** every test gets written pass/fail criteria before it runs; the failure paths must be proven, not just the happy path — filter binary deleted (TV still resolves within a defined number of seconds); kill -9 mid-apply; power-loss-equivalent during apply; router reboot / DHCP change (max-outage-seconds criteria); mid-session on/off toggle under active playback; HBC toggle / failsafe-cut interaction. Failing the gate → guard-only mode with honest limits, and all filter-dependent work is blocked-on-spike. (Spec §8)
- **Slice 0 deliverables:** boot-order trace on G1 (init.d hooks vs HBC's hosts bind-mount — prove which file edits the live sheet); mount-aware edit discipline; firewall chain contract; `/exec` ceilings measured on BOTH G1 and rugk's TV (timeout, output cap, spawn-vs-exec criteria, sentinel-file protocol); foreign-setup detector conditions enumerated; per-layer efficacy measurement (hosts-only vs filter-only vs combined with the proxy active) with the demotion rule; transport-tool validation; release-signing pricing; the kill matrix (kill filter / keeper / both, in all orders, with measured time-to-recovery and no persistent outage). (Spec §8)
- **Restore drill on both devices:** install → block → verify → restore → pass/fail checklist where every item is an observable command-output assertion (not "looks normal"), run on G1 and rugk's TV, with the pre-install baseline captured BEFORE install (hosts-content hashes, `iptables -S` dump, `ps` snapshot, connman flags). Checklist: `resolv.conf` bind-mount state restored; `connmand` dnsproxy flags restored; `/tmp/hosts` byte-compared to HBC-only content; named firewall chains DELETED (not just flushed) and jumps removed; keeper process AND its boot entry gone; post-restore DHCP renewal proof; HBC `blockUpdates` untouched; failsafe flag unset; streaming apps working; clean reboot. (Spec §8)
- **rugk's TV — clean-room compact:** baseline snapshot; the restore drill runs BEFORE any blocking tests; agreed time windows and his veto; log/data handling stated up front; the webOS 25/26 install workaround exercised (the stranger experience). (Spec §8, D10, D16)
- **Update drill:** install the current version → apply → install the next release over it → verify blocking still active, the pointer intact, settings and lists surviving. (Spec §5)
- **Store-listing gate:** symlinked hook; no system-area writes; real-TV test evidence captured; AI disclosure included. Checks: title ≤ 30 chars; category set; `rootRequired` in the manifest (not the YAML); `ipk-verify` run — noting the 25/26 workaround proves sideload, not catalog listing. (Spec §8, D6)
- **Build-slice tests:** shell — shellcheck (adapted target) + fixture tests with a stubbed PATH (idempotency, verify-then-commit, rollback completeness, marker-bounded hosts edits); filter — unit tests + fuzzing on the DNS wire parser; UI — status-parser unit tests against real script outputs as fixtures, including status-block version handling. Tests validate computed values, not just status codes; every bug fix gets a regression test. (Spec §3)

## 5. Module Mapping

Deep modules derived from the spec's architecture; each has a simple interface and rich internals. Step specifics follow the spec.

- **Boot reconciler (entry point).** Minimal script reached through the app's single startup pointer (symlink). Reconciles the version pointer against live state (from the update journal); if blocking is ON, re-applies; then exits. Deliberately tiny so it can never block TV startup. Interface: invoked by the TV's startup list; emits the standard status block; reads config + journal. Depends on: apply/verify scripts, config, journal.
- **Apply / verify / rollback scripts.** The blocking engine, in shell (glue only). Idempotent apply/status/rollback; every apply follows the fail-open order and self-verifies (apply → verify → commit, else rollback + report). Interface: fixed commands over the HBC bridge; status block out. Depends on: hosts overlay, firewall chains, filter config, lock discipline, logs.
- **Status emitter (contract).** Derives status from live probing at read time (filter socket, firewall `-C` checks, hosts-section hash) and frames it as `@@STATUS-BEGIN`/`@@STATUS-END` `key=value` lines; all other output goes to stderr/log; any status file is root-only. Interface: the status block the UI parses — never a cached file. Depends on: the live layers.
- **Keeper / supervisor.** Supervises the filter (restore system DNS first; bounded restart; re-flip after canary) and owns upstream re-learning (poll `connectionmanager/getStatus` + network-change signals; canary-verify; fail open on upstream failure). Interface: starts from boot; safe to re-run idempotently; reports through the status emitter. Depends on: filter daemon, system resolver, connectionmanager.
- **Filter daemon (+ config).** The on-TV DNS filter: every lookup checked against our list; blocked → nowhere, the rest → the network's upstream; `--selftest` supports verify-then-commit; hot config reload for list updates; small Go static binary shipped via the IPK (reuse-first decision in Slice 0). Interface: DNS socket on the chosen listen plan, selftest, reload. Depends on: upstream resolver, installed list input.
- **Update client (fetch / verify / swap / journal).** Fetches lists over HTTPS from our repo, checks SHA256 against the published sums, keeps the one-step-back copy, applies in fixed order under a single version pointer with a journal, and gates Safe (quiet) vs Strict (one-tap confirm). Interface: check-on-open (at most once per day) + "Update now"; freshness/status output. Depends on: transport tool, list parser/validator, apply scripts.
- **List parser / validator.** Validates list files line-by-line against a strict allowlist before use (a rejected file keeps the previous version) and computes live counts (unique effective hostnames, region filtering first) and freshness dates. Interface: accept/reject + parsed list + counts + dates. Depends on: the repo's list output format.
- **Web UI app.** HTML + TypeScript compiled to ES5. First-run checklist; main screen (one switch, Safe/Strict, live counts, dates, restore entry); "Something not working?" help with one-tap Safe; confirmation and needs-attention states. Talks only through the bridge contract; reads the status block; never parses un-delimited output. Depends on: HBC bridge, status emitter, fixed command set.
- **IPK packaging.** `ares-package` + dev-toolbox-cli manifest (`rootRequired` in the manifest), symlinked hook, no system-partition writes; GitHub releases host the `.ipk`; webosbrew catalog listing is the final milestone. Interface: the installable package + release assets (list sums; signatures if adopted). Depends on: TS bundle, Go binaries (armv7/arm64), scripts.
